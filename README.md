# LightSync

学生ライブの曲前MCで、観客が最後の8小節を「ギターソロ」と「客席と合唱」から選ぶローカル試作です。主催者は結果を確認し、演奏がその場面に入ったところで客席に色を送ります。

## 起動

MacにNode.js 24以降とXcodeを用意します。このディレクトリで次を実行してください。

```sh
npm ci
npm run lan
```

MacにStudioキー、6桁のイベントコード、観客用URLが表示されます。実機で使うときはMacと端末を同じWi-Fiに接続し、表示されたURLのうちMacのLANアドレスを使います。例は `http://192.168.1.2:8787` です。ゲストWi-Fiで端末間通信が遮断されている場合は、端末同士が通信できるネットワークを使用してください。Mac内だけの検証には `npm start` が使えます。

1. `LightSync.xcodeproj` をXcodeで開きます。スキーム **LightSyncStudio** を選んでiPhoneシミュレータ、または開発用iPhoneでRunします。実機ではSigning & Capabilitiesで自分のTeamを選び、必要に応じて一意のBundle Identifierを指定します。
2. StudioにMacのサーバーURLとStudioキーを入力します。会場用QRを作る場合、Studioをシミュレータで動かす場合もLANアドレスを入力します。`127.0.0.1` のQRは別のスマホから接続できません。
3. 観客はStudioの「参加用QR」を読み取るか、観客用URLをブラウザで開いて「参加する」を押します。ネイティブの観客アプリを試す場合は、別の端末で **LightSyncAudience** をRunし、URLとイベントコードを入力します。
4. Studioで「パープル」または「ミント」を押すと接続端末が点灯します。「全員を消灯」は受付中の投票も終了します。観客は「自分だけ消灯」で受信中も暗いままにできます。
5. 「投票を10秒開く」で二択を開始。10秒経過時の多数票を採用し、同票・無票時はギターソロに決定します。最後の8小節で「選ばれた結末の色を送る」を押します。受付・消灯直後は急な切り替えを抑えるため短い待ち時間があります。

## 確認

```sh
npm test
```

テストは投票の締切・重複・同票、本人の投票復元に使う参加ID、複数のWebSocket接続に対する点灯・停止、Studioの通信断を確認します。ブラウザ版は同一タブの再接続を同じ参加として扱い、タブを切り替えると受信を止めて前面復帰時に再接続します。

## この試作の範囲

- サーバー1プロセスにつき1公演・Studio1台です。Studioキーは運営者が保持し、観客に共有するのは参加用URLだけです。信頼できるローカルネットワークでのリハーサル用にHTTP／WSを使います。
- 色は合図を受信した時に変わります。時刻を予約して揃える配信、実会場での同期精度と接続台数の測定は今後の検証項目です。
- 投票・結果はメモリに保持します。再起動で公演コードとキーは変わり、状態も消去されます。二重送信の抑制は匿名の参加ID単位です。
- 料金徴収、ストアへの公開、演奏・音源の自動切替は含みません。バンドとMCが最終的な進行を担います。
